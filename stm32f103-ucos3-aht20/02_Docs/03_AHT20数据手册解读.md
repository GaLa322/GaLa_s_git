# AHT20 数据手册要点解读（任务二第 2 小问前置知识）

> 对应你给的 `AHT20产品手册a2.pdf`。手册原版是中文 + 英文对照，PDF 里中文有时复制出来是乱码，
> 但**关键数字和时序图都是英文**，不影响阅读。本文把写驱动真正需要的部分挑出来讲透。

---

## 1. 基本参数

| 参数 | 值 | 备注 |
| --- | --- | --- |
| 供电电压 | 2.2 V ~ 5.5 V | 本实验统一用 3.3 V |
| 通信接口 | I2C，最高 400 kHz | 支持标准模式/快速模式 |
| 7 位地址 | **0x38** | 固定，不可改 |
| 测温范围 | -40 ℃ ~ +85 ℃ | |
| 测湿范围 | 0 ~ 100 %RH | |
| 温度精度 | ±0.3 ℃（典型） | |
| 湿度精度 | ±2 %RH（典型） | |
| 温度分辨率 | 0.01 ℃ | 20 bit，200/2^20 |
| 湿度分辨率 | 0.024 %RH | 20 bit，100/2^20 |
| 单次测量时间 | 典型 80 ms | 手册给的最大值约 80 ms |
| 上电稳定时间 | ≥ 40 ms（建议 100 ms） | 代码里给了 100 ms |
| 长期漂移 | < 0.5 %RH/年 | |

> **注意**：精度是"典型值"，不是保证值。而且 AHT20 的湿度测量对**自加热**敏感——
> 如果采样太频繁（比如 100 ms 一次），芯片自身发热会让温度读数偏高 0.1~0.5 ℃。
> 手册建议采样间隔不要小于 1 s，本实验用 2 s，很安全。

## 2. 四个引脚

| 编号 | 名称 | 说明 |
| --- | --- | --- |
| 1 | VDD | 电源正，2.2~5.5 V |
| 2 | SDA | I2C 数据线（双向，开漏） |
| 3 | GND | 地 |
| 4 | SCL | I2C 时钟线（开漏） |

**最容易接错的地方**：AHT20 的引脚顺序是 **VDD-SDA-GND-SCL**，不是常见的 VDD-GND-SCL-SDA。
你给的图片里那句"注意管脚的编号和定义，接错会炸！！"就是指这个。接反 VDD/GND 会烧模块。

模块正面有孔（透气孔），**不要用手堵住、不要贴胶带**，否则湿度读数会长时间卡住不动。

## 3. 上电后的完整流程

### 3.1 上电

```text
上电 → 等待 ≥ 40 ms（代码给 100 ms）→ 读状态字节
```

### 3.2 读状态字节，检查 CAL 位

状态字节（`buf[0]`）：

```text
bit7  bit6  bit5  bit4  bit3  bit2  bit1  bit0
 BUSY   -     -     -    CAL    -     -     -
```

| 位 | 名称 | 含义 |
| --- | --- | --- |
| bit7 | BUSY | 1 = 正在测量，此时读到的数据无效 |
| bit3 | CAL | 1 = 已校准，0 = 未校准（需要发初始化命令） |

如果 `CAL = 0`，发初始化/校准命令：

```text
0xBE  0x08  0x00
```

参数 `0x08` 的含义：bit3 = 1 表示"使能校准输出"。发完等 10 ms 再读状态确认 CAL 变 1。
代码里最多重试 5 次。

### 3.3 触发一次测量

```text
0xAC  0x33  0x00
```

- `0xAC`：触发测量命令
- `0x33`：两个参数位（bit7 保留、bit6~5 保留、bit4 保留... 实际只用 `0x33` 这个固定值）
- `0x00`：第三个参数字节，固定 0

**发完必须等 80 ms** 才能读，否则 `buf[0]` 的 bit7 还是 1。

### 3.4 读 7 个字节

```text
START → 0x71(R) → ACK → byte0 … byte6 → NACK → STOP
```

> 注意：AHT20 **不需要**先写寄存器地址再读（它没有寄存器地址），直接读 7 字节即可。
> 这一点和 AT24C02 EEPROM 不同，是新手最容易照抄错的地方。

## 4. 数据帧格式（7 字节）

```text
byte0      byte1      byte2      byte3      byte4      byte5      byte6
┌────────┬──────────┬──────────┬──────────┬──────────┬──────────┬────────┐
│ 状态   │ 湿度     │ 湿度     │ 湿度高4位│ 温度     │ 温度     │ CRC8   │
│        │ bit19-12 │ bit11-4  │ 温度高4位│ bit15-8  │ bit7-0   │        │
└────────┴──────────┴──────────┴──────────┴──────────┴──────────┴────────┘
```

`byte3` 被两个量**共用**：高 4 位是湿度的最低 4 位，低 4 位是温度的最高 4 位。
这是最容易写错的一行代码：

```c
raw_humi = ((uint32_t)buf[1] << 12) | ((uint32_t)buf[2] << 4) | ((uint32_t)buf[3] >> 4);
raw_temp = (((uint32_t)buf[3] & 0x0FU) << 16) | ((uint32_t)buf[4] << 8) | ((uint32_t)buf[5]);
```

注意 `buf[6]` 是 CRC，**绝对不能**拼进温度里。

### 4.1 换算公式

```text
湿度(%RH) = raw_humi / 2^20 × 100
温度(℃)   = raw_temp / 2^20 × 200 − 50
```

`2^20 = 1048576`（20 bit 满量程）。

### 4.2 完整算例（可以对着手册验算）

假设读到这样一帧：

```text
1C  8F  3B  66  1E  B8  6D
```

**第一步：看状态**

`0x1C = 0001 1100`：bit7=0（不忙），bit3=1（已校准）。可以取数据。

**第二步：拼湿度**

```text
raw_humi = (0x8F << 12) | (0x3B << 4) | (0x66 >> 4)
         = 0x8F000 | 0x3B0 | 0x6
         = 0x8F3B6
         = 586678
```

```text
湿度 = 586678 / 1048576 × 100 = 55.948... ≈ 55.95 %RH
```

**第三步：拼温度**

```text
raw_temp = ((0x66 & 0x0F) << 16) | (0x1E << 8) | 0xB8
         = (0x6 << 16) | 0x1E00 | 0xB8
         = 0x61EB8
         = 401080
```

```text
温度 = 401080 / 1048576 × 200 − 50
     = 0.382499... × 200 − 50
     = 76.4998 − 50
     = 26.50 ℃
```

**第四步：验 CRC**

对前 6 个字节做 CRC8（多项式 0x31，初值 0xFF）：

```text
CRC8(1C 8F 3B 66 1E B8) = 0x6D = byte6 ✓
```

所以这一帧是合法的：**T = 26.50 ℃，H = 55.95 %RH**。

### 4.3 CRC8 实现

```c
static uint8_t AHT20_Crc8(const uint8_t *data, uint8_t len)
{
    uint8_t crc = 0xFFU;              /* 初值 0xFF */
    for (uint8_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t bit = 0; bit < 8; bit++) {
            crc = (crc & 0x80U) ? (uint8_t)((crc << 1) ^ 0x31U)
                                : (uint8_t)(crc << 1);
        }
    }
    return crc;
}
```

参数对照：多项式 `0x31`（即 x^8 + x^5 + x^4 + 1），初值 `0xFF`，不反转，不异或输出。
计算结果与 `buf[6]` 比较。

> **实战建议**：CRC 不通过**不应该**直接丢弃数据。有些便宜模块的 CRC 实现不规范（甚至固定发 0），
> 全丢会导致"一直读不到数据"。本工程的做法是：**照常显示数值，CRC 结果放在内部标志里**
> （`AHT20_LastCrcOk()`），默认不往串口打；调试时把它临时拼进打印即可：
> `BSP_UART_Printf("T=%s C  H=%s %%RH  (CRC %s)
", t, h, AHT20_LastCrcOk() ? "ok" : "NG");`
> 如果长期 NG 且数据明显乱跳，再考虑检查接线/上拉。

## 5. 命令一览

| 命令 | 字节序列 | 作用 |
| --- | --- | --- |
| 初始化/校准 | `0xBE 0x08 0x00` | 使能校准输出，上电 CAL=0 时发 |
| 触发测量 | `0xAC 0x33 0x00` | 启动一次温湿度转换 |
| 软复位 | `0xBA` | 复位芯片（本工程未用，调试可用） |
| 读状态 | 直接读 1 字节 | 查 BUSY/CAL |

软复位用法（卡死时救命）：

```c
uint8_t cmd = 0xBA;
BSP_I2C_Write(0x38, &cmd, 1);
HAL_Delay(20);            /* 复位后等 20 ms 再重新初始化 */
```

## 6. 时序上的几个"必须"

| 要求 | 数值 | 违反的后果 |
| --- | --- | --- |
| 上电到第一次通信 | ≥ 40 ms | 读不到数据 / NACK |
| 触发到读取 | ≥ 80 ms | 读到 BUSY=1，数据无效 |
| 两次测量之间 | 建议 ≥ 1 s | 自加热导致温度偏高 |
| SCL 频率 | ≤ 400 kHz | 通信失败 |
| 上拉电阻 | 4.7 kΩ（典型） | 无上拉 = 永远 NACK |
| 总线电容 | ≤ 400 pF | 线太长导致上升沿变缓、误码 |

## 7. 和 SHT30 / DHT11 的简单对比（写报告可以用）

| 型号 | 接口 | 精度 | 价格 | 特点 |
| --- | --- | --- | --- | --- |
| DHT11 | 单总线（自定义） | ±2 ℃ / ±5 %RH | 最便宜 | 时序苛刻，慢（1 s 一次），精度低 |
| **AHT20** | **I2C** | **±0.3 ℃ / ±2 %RH** | 便宜 | 性价比高，带 CRC，本实验用 |
| SHT30 | I2C | ±0.3 ℃ / ±2 %RH | 稍贵 | 工业级，可配地址，带加热器 |

AHT20 是"便宜够用"的典型：I2C 标准接口、20 bit 分辨率、自带 CRC、封装小。
缺点是**没有可配置地址**（一条总线只能挂一个），以及**长期在高湿环境下的漂移**需要定期校准。

## 8. 驱动里那些"看起来多余"的代码，其实都有原因

| 代码 | 原因 |
| --- | --- |
| `HAL_Delay(100)` 上电延时 | 手册要求 ≥ 40 ms，给足余量 |
| 先读一次状态再判断 CAL | 这一读顺便验证了 I2C 通不通（NACK 立刻暴露） |
| 发完校准命令后回读确认 | 有些模块第一次上电 CAL 起得慢，重试 5 次更稳 |
| 读数据后检查 bit7 | 80 ms 是典型值，个别模块要更久，BUSY 就再等 10 ms |
| CRC 失败仍然打印 | 便于区分"模块 CRC 不规范"和"接线有问题" |
| `AHT20_MEASURE_MS` 做成宏 | 不同批次模块需要的等待时间不同，方便调 |

## 9. 附：为什么湿度要除以 2^20 而不是 2^16

因为 AHT20 输出的是 **20 bit** 数据（不是常见的 16 bit）。20 bit 能表示 1048576 个刻度，
把满量程 100 %RH 分成 1048576 份，分辨率就是 100/1048576 ≈ 0.000095 %RH（理论值）。
温度同理：量程跨度是 200 ℃（-50 ~ +150），所以乘 200 再减 50。

如果按 16 bit 算，读数会小 16 倍，表现为"湿度永远 3%、温度永远 -48 ℃"——
这是新手最常见的 bug 之一，看到这种离谱数值先检查移位。
