##### 4.3 `RTOS/uC-OS3/Ports/ARM-Cortex-M/ARMv7-M/ARM/os_cpu.h`

原版用 armcc(AC5) 的宏判断有没有硬件 FPU：

```c
#ifndef  __TARGET_FPU_SOFTVFP
#define  OS_CPU_ARM_FP_EN   1u      /* 以为有 FPU */
```

**AC6(ARMCLANG) 从不定义 `__TARGET_FPU_SOFTVFP`**，于是 Cortex-M3（没有 FPU）被当成有 FPU。改成：

```c
#ifndef  OS_CPU_ARM_FP_EN
#if  (defined(__ARM_FP) && defined(__FPU_PRESENT) && ((__FPU_PRESENT) == 1u)) && \
     !defined(__TARGET_FPU_SOFTVFP)
#define  OS_CPU_ARM_FP_EN   1u      /* 真有 FPU：M4F / M7 */
#else
#define  OS_CPU_ARM_FP_EN   0u      /* 无 FPU：M3（STM32F103）*/
#endif
#endif
```

### 四、任务二：I2C 总线与 AHT20 温湿度采集

#### 1. 软件 I2C 和硬件 I2C

**I2C 的物理层只有两根线**：SCL（时钟）、SDA（数据），都是**开漏输出 + 外部上拉**。开漏意味着任何设备只能把线拉低，不能主动拉高——所以多设备挂同一总线时不会短路，这就是"线与"；两个设备同时发不同数据时，谁发 0 谁就"赢"，输的一方自动退出，这就是**仲裁**。

**硬件 I2C**：STM32 内部有一个 I2C 外设，你只要把数据塞进 `DR` 寄存器，起始位、地址、ACK、停止位由硬件自动产生，还能用中断/DMA。CPU 负担小、时序准。

```c
HAL_I2C_Master_Transmit(&hi2c1, 0x38 << 1, buf, len, 50);
HAL_I2C_Master_Receive (&hi2c1, 0x38 << 1, buf, len, 50);
```

**软件 I2C**：不用外设，用两个普通 GPIO 配成开漏，**代码里手动把 SCL/SDA 拉高拉低**，自己凑出 START、字节、ACK、STOP。时序全靠延时函数。

```c
static void I2C_Start(void)
{
    SDA_HIGH(); I2C_DelayUs(2);
    SCL_HIGH(); I2C_DelayUs(2);
    SDA_LOW();  I2C_DelayUs(2);      /* SCL 高时 SDA 下降 = START */
    SCL_LOW();  I2C_DelayUs(2);
}
```

对比：

| 维度 | 软件 I2C | 硬件 I2C |
| --- | --- | --- |
| 用的引脚 | 任意两个 GPIO | 固定复用引脚（PB6/PB7） |
| 速度 | 几十~200 kHz（受延时精度限制） | 100 k / 400 k / 1 M |
| CPU 占用 | 全程忙等，占用高 | 硬件搬运，占用低 |
| 移植性 | 换芯片几乎不改 | 换系列要重写初始化 |
| 调试难度 | 全部可控，能单步 | STM32F1 的硬件 I2C 有已知勘误，容易卡 BUSY |
| 本项目实现 | `Src/bsp_i2c_sw.c` | `Src/bsp_i2c_hw.c` |

本工程把两者做成了**同一套上层驱动、编译期切换**，`board_config.h` 一个宏：

```c
#define APP_I2C_USE_SOFT   0    /* 0 = 硬件 I2C1；1 = GPIO 模拟 */
```

AHT20 驱动只认 `BSP_I2C_Write()/BSP_I2C_Read()` 三个函数，所以换实现不用动传感器代码。

#### 2. AHT20 温湿度模块（由数据手册得到）

| 参数 | 值 |
| --- | --- |
| 供电 | 2.2 ~ 5.5 V |
| 7 位地址 | **0x38**（写 0x70 / 读 0x71） |
| 温度范围 / 精度 | -40 ~ 85 ℃，±0.3 ℃ |
| 湿度范围 / 精度 | 0 ~ 100 %RH，±2 %RH |
| 分辨率 | 0.01 ℃ / 0.024 %RH |
| 一次测量时间 | **80 ms** |
| 上电稳定 | ≥ 40 ms |

四个命令：

| 命令 | 作用 |
| --- | --- |
| `0xBE 0x08 0x00` | 初始化/校准（CAL 位清零时发） |
| `0xAC 0x33 0x00` | 触发一次测量 |
| `0xBA` | 软复位 |
| 读 7 字节 | `状态, 湿度[19:12], 湿度[11:4], 湿度[3:0]+温度[19:16], 温度[15:8], 温度[7:0], CRC8` |

状态字节两个位最关键：

```text
bit7 = BUSY  1 = 正在测量，此时读数据无效
bit3 = CAL   1 = 已校准
```

数据换算（20 位原始值）：

```c
raw_humi = ((b1 << 12) | (b2 << 4) | (b3 >> 4));
raw_temp = (((b3 & 0x0F) << 16) | (b4 << 8) | b5);

humidity    = raw_humi * 100.0f / 1048576.0f;          /* 2^20 */
temperature = raw_temp * 200.0f / 1048576.0f - 50.0f;
```

#### 3. 驱动

三层结构：

```text
aht20.c        业务：初始化、触发、读、算温湿度、CRC 校验
   ↓ 只依赖
bsp_i2c.c      传输：BSP_I2C_Write / BSP_I2C_Read（软/硬二选一）
   ↓ 依赖
HAL / GPIO     STM32 底层
```

初始化：

```c
uint8_t AHT20_Init(void)
{
    uint8_t st = 0;

    AHT_Delay(100);                       /* 上电稳定 */
    if (!BSP_I2C_Read(AHT20_I2C_ADDR7, &st, 1)) return AHT20_ERROR;
    if ((st & 0x08) == 0)                 /* CAL 未校准 */
    {
        uint8_t cmd[3] = {0xBE, 0x08, 0x00};
        if (!BSP_I2C_Write(AHT20_I2C_ADDR7, cmd, 3)) return AHT20_ERROR;
        AHT_Delay(10);
    }
    return AHT20_OK;
}
```

一次完整测量：

```c
uint8_t AHT20_ReadBlocking(float *t, float *h)
{
    uint8_t cmd[3] = {0xAC, 0x33, 0x00};
    uint8_t buf[7];

    BSP_I2C_Write(AHT20_I2C_ADDR7, cmd, 3);   
    AHT_Delay(80);                            

    if (!BSP_I2C_Read(AHT20_I2C_ADDR7, buf, 7)) return AHT20_ERROR;
    if (buf[0] & 0x80) return AHT20_BUSY;     

    ...
    return AHT20_OK;
}
```

`AHT_Delay()` 要在两种场景下都能用：

```c
static void AHT_Delay(uint32_t ms)
{
#if (APP_USE_UCOS3 != 0)
    if (OSRunning == OS_STATE_OS_RUNNING)     
    {
        OS_ERR err;
        OSTimeDly(ms, OS_OPT_TIME_DLY, &err);
        return;
    }
#endif
    HAL_Delay(ms);                            
}
```

### 五、实验总结

（1）本次实验任务一完成 uC/OS-III 在 STM32F103C8T6 上的移植：把内核、CPU 移植层、基础库源码按"层级不能改"的规则放进工程，改 4 处配置（优先级数量、内存池、优先级位数、FPU 判断），把 SysTick 和 PendSV 两个中断交给内核，`OSInit → 创建任务 → OS_CPU_SysTickInit → OSStart` 四步启动，最终三个任务按 1 s / 3 s / 2 s 的节奏各自独立运行。移植过程中理解了 RTOS 的核心机制：每个任务有独立的 TCB 和栈，`OSTimeDly` 是把任务挂到延时链表上主动让出 CPU，PendSV 负责上下文的保存与恢复，SysTick 提供 1 ms 节拍。

（2）任务二完成 I2C 总线通信与 AHT20 采集：理解了 I2C 的开漏输出、线与、外部上拉、ACK/NACK、起始停止条件；区分了软件 I2C（GPIO 位翻转、时序可控、占用 CPU）与硬件 I2C（外设自动产生波形、速度快、STM32F1 有勘误易卡 BUSY）；按手册实现 0x38 地址的初始化、触发、7 字节读取、20 位数据换算与 CRC8 校验；把task3 改成每 2 s 采集一次，串口输出的同时两个 LED 仍精确闪烁。

（3）最深的体会是 RTOS 存在的意义：AHT20 一次测量要等 80 ms，裸机里 `HAL_Delay(80)` 会把整个 CPU 一起停住，灯的周期被拖成 1.08 s；换成 `OSTimeDly(80)` 后任务只是被挂起，CPU 立刻切去跑 LED 任务，两个任务的节奏互相不干扰。这就是"实时"两个字的具体含义——**不是跑得快，而是该响应的时候一定能响应**。
